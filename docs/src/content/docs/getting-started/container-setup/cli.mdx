---
title: Using the CLI (wx start)
description: Start agent-wechat with a single command.
---

The simplest way to run agent-wechat. During P1-A, build the repository image locally and use `pnpm cli start`; it creates the container with the correct flags and starts it. After P1-B, `--image` may select an exact verified fork semver/digest, with no `latest` or registry fallback.

:::tip
Don't want to manage Docker yourself? See [Managed Hosting](/hosting/managed-hosting) for a fully hosted option.
:::

## Start the container

```bash
pnpm cli start
```

This starts a container named `agent-wechat` with:
- **Port 6174** exposed — REST API + VNC web viewer at `/vnc/`
- Persistent volumes for data and WeChat home directory
- Auth token from `~/.config/agent-wechat/token` (auto-generated on first run)

## With a proxy

To route all container traffic through a proxy:

```bash
# HTTP proxy
pnpm cli start --proxy user:pass@host:port

# SOCKS5 proxy
pnpm cli start --proxy socks5://user:pass@host:port
```

This sets up a transparent proxy (redsocks + iptables) inside the container — invisible to WeChat.

## Stop the container

```bash
pnpm cli stop
```

This stops and removes the container. Your data persists in Docker volumes.

## When to use this vs Docker Compose

Use `wx start` when:
- Running locally for development or personal use
- You don't need custom networking
- You want the simplest possible setup

Use [Docker Compose](/getting-started/container-setup/docker-compose) when:
- Running in production alongside other services (e.g., OpenClaw)
- You need the container on a custom Docker network
- You want more control over the configuration
