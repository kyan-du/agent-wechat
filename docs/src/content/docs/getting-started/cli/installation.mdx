The `wx` CLI lets you manage the agent-wechat container and interact with WeChat from your terminal.

## Install

```bash
# Pending P1-B (not available yet): npm install -g @kyan-du/agent-wechat-cli
```

This installs the `wx` command globally.

## Migrate an older global installation

Repository package history identifies the former CLI as `@thisnick/agent-wechat-cli`; it and the fork package both install the `wx` binary. Remove the former package first:

```bash
npm uninstall -g @thisnick/agent-wechat-cli
```

The fork package is not published yet, so use a repository checkout: clone it, run `corepack enable && pnpm install --frozen-lockfile`, then `pnpm build && pnpm build:image`. Invoke commands from that checkout as `pnpm cli <arguments>`.

If the historical root CLI left an unsafe persisted session, do not repair or migrate it. Stop old agent-wechat containers, then delete **only** its `sessions` directory at the data location defined by the root CLI source:

- macOS: `rm -rf "$HOME/Library/Application Support/agent-wechat/sessions"`
- Linux: `rm -rf "${XDG_DATA_HOME:-$HOME/.local/share}/agent-wechat/sessions"`
- Windows PowerShell: `Remove-Item -Recurse -Force "$([Environment]::GetFolderPath('ApplicationData'))\agent-wechat\sessions" -ErrorAction SilentlyContinue`

Start from the built checkout and authenticate fresh:

```bash
pnpm cli up
pnpm cli auth login
```

Only after a future P1-B actually publishes and verifies `@kyan-du/agent-wechat-cli` should you install it with `npm install -g @kyan-du/agent-wechat-cli`; then use `wx up` and `wx auth login`.

## Prerequisites

- **Node.js >= 22**
- **Docker** installed and running

## Verify installation

```bash
pnpm cli --version
```

## Configuration

The CLI reads configuration from:

| Source | Description |
|--------|-------------|
| `AGENT_WECHAT_URL` | Server URL (default: `http://localhost:6174`) |
| `AGENT_WECHAT_TOKEN` | Auth token (overrides token file) |
| `~/.config/agent-wechat/token` | Auto-generated auth token (created on first `wx up`) |

The auth token is generated automatically on first run and shared with the container via a read-only volume mount.

| Option | Description |
